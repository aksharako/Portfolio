01 / the brief

Make analytics feel like a game, not homework.

BAXA — the Business Analytics Association at McCombs — wanted an escape-room-themed hackathon for Spring 2026. Teams would move through a series of rooms, each unlocked by solving a data analytics puzzle in code.

Off-the-shelf hackathon platforms are made for developers — cold, terminal-first, dashboard-heavy. That was the exact vibe we didn't want. The goal was to pull in business students, marketers, and even fine arts folks who'd never touched Python.

I built the whole thing solo — the app, the database, the brand system, and every piece of print collateral. Design and code together, not a handoff.

02 / the app

Real Python. In the browser.

Teams write actual Python — pandas, matplotlib, numpy — and it runs client-side via Pyodide (WebAssembly). No servers to spin up, no code sandboxes to maintain, no cost per user. The escape room scales for free.

Under the hood: Next.js 14 App Router with TypeScript, Tailwind for styling, Monaco Editor (the same editor VS Code uses) for the code input, Pyodide to execute Python + numpy + matplotlib in a WebAssembly sandbox, and Supabase Postgres for teams, progress, and code submissions.

Security wasn't optional — this ran under real team credentials. Every table has Row Level Security policies, passwords are bcrypt-hashed, the Supabase service key stays server-side, and the Pyodide sandbox has no file system, no network, and no shell access.

03 / design decisions

Design the vibe first, the interface second.

Most escape rooms lean into stress — flashing red timers, dark themes, dramatic music. I went the other direction: warm coral over cold blue, rounded corners over sharp edges, locks and progress bars borrowed from mobile games. A puzzle you want to solve, not one you're afraid of failing.

i.

Playful palette

Coral gradients instead of BI-dashboard blue. Fun without becoming toy-like.

ii.

Progress you feel

Every room adds a filled slot. Momentum you can see.

iii.

Clues, not questions

Prompts written as riddles, not exam problems.

06 / what I learned

Doing everything changes everything.

Being the designer and the engineer collapsed the usual handoff. Design decisions I'd normally have to explain in a spec — spacing, states, edge cases — I just built. And engineering constraints I'd normally hear about too late — Pyodide's 50MB load, Supabase's row limits, matplotlib rendering timing — I could design around from day one.

The one thing that mattered most: I picked the technical stack for the experience, not for my resume. Pyodide meant zero backend cost, which meant we could actually run the event. Supabase meant real auth in an afternoon. That's the tradeoff any product person eventually has to make — and I got to feel it end-to-end.

"The design changes who shows up. That's the whole job."
